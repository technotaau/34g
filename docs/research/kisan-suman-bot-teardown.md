# KISAN 2026 का "Suman" आवाज़-सहायक: यह कैसे बना है

TechnoTaau Team शोध सत्र, 26 सितंबर 2026। स्रोत: https://2026.kisan.in का सार्वजनिक HTML और उसमें जुड़े widget `https://exhsupportai.kisan.in/?lang=hi` का सार्वजनिक JavaScript, जैसा हर browser को मिलता है। उनके server से कोई बातचीत या API call नहीं की गई। उनका code इस repo में नहीं रखा गया, केवल यह विश्लेषण।

## ढांचा

| परत | क्या मिला |
|---|---|
| वेबसाइट | Wix पर बनी। "Suman Chat Bot" नाम का custom code, जो पन्ने के कोने में एक iframe (`exhsupportai.kisan.in`) लगाता है और उसे `allow="microphone; autoplay"` देता है। होमपेज पर 3 सेकंड बाद "Talk to Suman" वाला GIF popup। मराठी पन्नों (`/mr`) पर widget अपने-आप खुलता है। |
| widget | एक ही HTML file, सारा JavaScript अंदर। फ़ोन का mic `getUserMedia` से, 16 kHz mono; आवाज़ के 16-bit PCM टुकड़े सीधे WebSocket पर भेजे जाते हैं। |
| server | `wss://api.kisan.com/voice` (उनका अपना server)। Code की टिप्पणियों में साफ़ लिखा है कि यह server **Google Gemini Live** से जुड़ता है ("Gemini speaks greeting", "Gemini Live session-duration limit", "Gemini code 1008")। जवाब में 24 kHz की आवाज़ के टुकड़े आते हैं। 16 kHz अंदर और 24 kHz बाहर, Gemini Live के audio format से मेल खाते हैं। |
| बातचीत के संदेश | `user_transcript` और `thea_transcript` (आवाज़ के साथ लिखा पाठ भी), `turn_complete`, `interrupted` (बीच में बोलने पर bot रुकता है), `session_handle` (दोबारा जुड़ने पर वहीं से), `session_timeout` |
| bot के "काम" (tools) | `navigate` (किसी pavilion या stall का पन्ना नई tab में खोलना), `link_button` (form का बटन), `lead_field_updated` और `lead_saved` (नाम, फ़ोन, email, कंपनी लेना; यानी बिक्री के lead), `typed_input` (फ़ोन नंबर जैसी चीज़ बोलने की जगह टाइप करवाना), `meet_pending` (किसी इंसान से मीटिंग की मांग और उसकी स्थिति) |
| याद रखना | पन्ना refresh हो तो पिछली बातचीत का पाठ `/resume/save` और `/resume/load` से वापस मिलता है, और server उसे Gemini के निर्देश में जोड़ देता है, ताकि वह परिचय न दोहराए और उसी भाषा में आगे बढ़े। |
| भाषा | `lang=hi`, `mr` या `en`, पन्ने के रास्ते से तय; server उसी भाषा में अभिवादन करवाता है। |
| माप | हर कदम पर Google Analytics events (`suman_popup_shown`, `suman_popup_talk`...) |

## "AI को train किया है?" नहीं

Code से साफ़ है कि यह एक आम आवाज़ वाला AI मॉडल (Gemini Live) है, जिसे server की तरफ़ से **निर्देश (system prompt) में प्रदर्शनी की जानकारी** और कुछ **tools** दिए गए हैं। कोई अलग training नहीं। यही तरीका हमारे bot का भी है: जांचे हुए तथ्य निर्देश में, और कुछ काम tools से। फ़र्क केवल आवाज़ वाली परत का है: उनका मॉडल आवाज़ सुनकर सीधे आवाज़ में बोलता है, इसलिए बातचीत इतनी "smooth" लगती है।

## 34 गांव के लिए क्या सीखें

**वैसा ही करें:**
1. बोलकर बात, और साथ में लिखा पाठ भी दिखे (बुज़ुर्ग सुनें, युवा पढ़ें)।
2. बीच में टोकने पर bot रुक जाए।
3. पन्ना बंद होकर फिर खुले तो बातचीत वहीं से चले।
4. Tools से काम: "कुम्भाणा का पन्ना खोलो" (navigate), "यह याद सहेज लो" (हमारा `extract_memory`), "नक्शे पर दिखाओ"।
5. नाम या गांव जैसी चीज़ बोलने में दिक्कत हो तो टाइप करने का डिब्बा अपने-आप आए।
6. एक पहचान वाला नाम और चेहरा (उनकी "Suman")। हमारे लिए नाम team तय करे।
7. होमपेज पर कुछ सेकंड बाद एक बार का निमंत्रण ("अपने गांव की बात सुनाइए"), और फिर न दिखे।

**वैसा न करें:**
1. फ़ोन नंबर और email "lead" की तरह इकट्ठा करना। हमारे यहां यह DPDP और भरोसे, दोनों के ख़िलाफ़ जाता है। संपर्क केवल जब कोई ख़ुद चाहे, और अलग सहमति से।
2. बिना पूछे mic या popup बार-बार खोलना।

## हमारे लिए आवाज़ वाली परत के तीन रास्ते

| रास्ता | कैसा लगेगा | अच्छा | ध्यान रखें |
|---|---|---|---|
| **A. आज वाला** (कीबोर्ड mic से बोलकर लिखना, Claude से जवाब, फ़ोन की आवाज़ में "सुनिए") | एक-एक बारी, चैट जैसा | सबसे सस्ता, तथ्य पक्के, पायलट चालू | "smooth" बातचीत नहीं |
| **B. आवाज़ → पाठ → Claude → आवाज़** (हमारे backend में) | 2-4 सेकंड रुककर जवाब | तथ्यों पर पूरा नियंत्रण; हर बात का पाठ और आवाज़ सुरक्षित; STT और आवाज़ वाली सेवा बदल सकते हैं | तीन सेवाएं जोड़नी होंगी; बीच में टोकना मुश्किल |
| **C. Suman जैसा सीधा आवाज़ मॉडल** (Gemini Live जैसा realtime voice model; हमारे तथ्य tool से) | फ़ोन पर बात करने जैसा | सबसे स्वाभाविक; बुज़ुर्गों से "interview" लेने के लिए सबसे अच्छा | प्रति मिनट ख़र्च ज़्यादा; अपना WebSocket server चाहिए; मॉडल कभी-कभी तथ्य से बाहर बोल सकता है, इसलिए सख़्त निर्देश और tool से तथ्य देना ज़रूरी; बागड़ी समझ परखनी होगी |

**सुझाव:**
1. **"बताइए" (यादें इकट्ठा करना):** रास्ता C सबसे ज़्यादा फ़ायदा देगा। bot बुज़ुर्ग से धीरे-धीरे सवाल पूछे, सुने और आगे के सवाल करे। पूरी आवाज़ और पाठ सहेजा जाए और team जांचे।
2. **"पूछिए" (जानकारी देना):** पहले रास्ता A या B से, क्योंकि यहां तथ्यों का सही होना सबसे ज़रूरी है।
3. **शुरुआत कैसे करें:** पहले 20 बुज़ुर्गों की बागड़ी clips पर दोनों तरह के मॉडल परखें, फिर तय करें।
4. **दाम:** हर सेवा के दाम और भाषाएं उसी समय उनकी साइट पर जांचें। इस विश्लेषण में कोई दाम नहीं लिखा, क्योंकि वे जल्दी बदलते हैं।
